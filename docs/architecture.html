1Overview

A person types a message in English. A spell checker corrects near-miss words first. Then three independent readers each turn the message into the same small language, SOP (one line per request, called a wire). Each reader has its own copy of the same engine and its own drawing, so the three results can be compared side by side. The engine executes the wires through plugins; graph and logic questions are answered by a small Datalog evaluator inside the engine.

2SOP: the wire language, the legend, the plugins

A wire is one line: @id type key=value key=value …. Wires are single-assignment: a wire is defined once and a later wire refers to it as $id (the parser rejects a reference to a wire not yet defined). A value can be a list (from=A,B) or a quoted string. Parser and serializer: parse and serialize in docs/js/logic.js (section 1 of that file).

The Rules reader turns “Draw a red circle named Hub below Start and connect Start to it. How many circles are there?” into:

@s1 command action=create shape=circle color=red name=Hub position=below anchor=Start
@s2 command action=connect from=Start to=$s1
@s3 question ask=count shape=circle

Wire types (5)

TypeMeaning (the core plugin's own words)
commandSomething the user wants done (key action: 21 values).
questionSomething the user wants to know (key ask: 17 values). Never changes the drawing.
factA statement that should hold in the world (“Start is red”).
ruleA default that applies to future shapes (“from now on circles are orange”).
mentionA description that must resolve to existing shapes (“the red circle”, “all stars that are not blue”). The engine resolves it against the canvas when it executes; no reader needs the drawing.

The legend: the single hand-written spec

The legend is the set of questions a wire can answer (its keys) and, for each, its allowed values. Plugins declare it with legend.define(plugin, key, spec) (class Legend in docs/js/logic.js): ask (the question in words), kind (enum, number, text) and, for enums, each value with its cue words (SHAPE_VALUES, COLOR_VALUES, …). Today: 32 keys; action has 21 values (create, delete, move, set, resize, rename, label, duplicate, swap, group, ungroup, connect, disconnect, align, arrange, distribute, toFront, toBack, undo, redo, forget), ask has 17 (count, list, exists, property, check, describe, neighbors, connected, degree, nearest, extreme, path, reachable, cycle, members, groupOf, rules). Counted in node from createSystem() on 2026-11-02.

AGENTS.md: the legend is the only hand-written input of a learned reader. The VSS worlds learn every mapping from words to the legend (verbs, values, how to cut) from the annotated data; hand-written word tables are allowed only in the Rules reader.

The demo's SOP language and Capabilities tabs (docs/js/help.js) are generated at run time from this legend and the plugin list, so they cannot drift from the engine.

Plugins = capabilities (11)

The Engine holds a list of plugins. Each plugin adds wire types, legend keys and handlers; a wire is executed by the enabled handler whose type and when pattern match its arguments (higher priority first, then the more specific pattern). A message's wires run in order as one undo step (Engine.run); each wire is applied whole or not at all, a wire that fails is reported and the wires that depend on it are skipped, the others still run. A plugin can be switched off in the Capabilities list; the switch applies to every reader, and a wire that needs that plugin then fails with a message naming it.

3The Rules reader

Code: makeFormalizer(engine) in docs/js/logic.js (section 6 of that file). Hand-written, deterministic, instant.

  1. Spelling: a word close (OSA edit distance 1, or 2 for words of 7+ letters) to a legend cue word or a canvas name is replaced; names introduced by “named / called” and quoted text are left alone. (This runs in addition to the VSA spell checker of section 6.)
  2. Cut: sentences are split at . ! ? ;; a sentence is split again at a comma or an “and” that stands right before a verb cue (SPLIT_VERB). The pieces are the requests; the Neural reader reads these same pieces.
  3. Reading: regular expressions over the legend's cue words (shapes, colours, sizes, actions, positions) and their order. Cue words are the legend values' hand-written cues plus docs/js/learned-cues.js, generated by training/sketch/learn_triggers.py from the trigger words annotated in the training messages.

Fair comparison rule (AGENTS.md): Rules and VSS use the same legend and the same cue list (training/sketch/export_cues.mjs → training/sketch/make_normalizer.py); a cue added for one is added for both, and only from training data.

4The VSS reader: the composer

VSS = vector-symbolic. The VSS reader is not one model: it is a composer of small models, built in docs/js/vss-composer.js (class Composer, loadComposer) from docs/model/micro/registry.json, and loaded on first use by docs/js/vss-formalizer.js (loadComposerAt, versioned URLs). There are two cutters: the world cutter cuts and routes; the event cutter only gives a hint.

(a) The world cutter

docs/model/micro/cutter_worlds7s.json (1.14 MB). A token tagger: a greedy averaged-perceptron BIO tagger (the segmenter of training/sketch/front.py, train_segmenter; JS twin segmentWorlds in docs/js/front.js). Each token gets B-<world> (the first token of a request, labelled with the world that holds its action), I (inside the request) or O (outside every request: chatter). 9 labels: 7 worlds, I, O. A unit runs from a B to the last I after it.

The unit's candidates are the 3 worlds with the highest B-<world> score at its first token (ROUTER_K = 3: the smallest k whose recall of the gold world is at least 97%, measured 97.9% by training/sketch/cutter_worlds_probe.py).

Trained by training/sketch/train_cutter.py --worlds on the annotation spans (the span of each gold request gives its B and I tokens), seg_epochs 8, on 6640 messages / 224,724 tokens: the 3640 long messages with spans plus the 3000 short one-request commands (switch SHORT=1). The “s” in the name is that switch (SHORT.md). Training takes about 82 s on CPU.

(b) The 7 micro-worlds

A world is one VSS model for a few actions (its events). Its legend lists only its own events. The model is a route book over stars: every word identity is a vector of D = 1024 unit-modulus complex numbers derived from a hash of its name (portable star_version 2, docs/js/vss/stars.js); the learned route book (docs/js/vss/routebook.js) gives each token an address from its path, bigram and position, and the reader (docs/js/vss/reader.js) decodes the frame: the predicate (which event, from the world's verb lemmas) and the role fillers (target, colour, landmark, …). The reader returns a status: ok, abstain (margin under 0.05: uncertain, still executed today), unknown-event (no action word found) or no-sense (more than half of the tokens could not be placed).

Before the model, the world's own front end front.json normalizes the tokens: learned value n-grams (“bottom right” → bottom_right) and trigger rules, learned from the annotated rows of that world's events only (FRONT_ROWS=world; thresholds val_min_count 5, val_min_prec 0.8, trig_min_count 2, trig_share 0.75, trig_min_prec 0.6). Names are never in the lexicon: an unknown word becomes a name token, quoted text a text token.

(c) The event cutter and the event hint H1

docs/model/micro/cutter_events.json (1.24 MB): the same tagger and trainer, with one label per legend event (B-<event>, 35 events, plus I and O; grouping training/sketch/worlds_micro/GROUPS_EVENTS.json), trained on the 3640 long messages (not on the short commands). It is decoded once over the whole message; it does not cut. A unit's hint is the B-<event> label with the largest score at the unit's first token.

Why: inside a world with several events the reader decides the event only from a verb lemma; a request with no verb (“Post blue”, “Alpha to Beta”) gets unknown-event. H1 (registry "event_hint": "H1"): only when a candidate world's reading has status unknown-event and the hint is one of that world's events, the world reads the unit again with that event given (opts.event in reader.js). Measured gain on the sample: right 69.6 → 73.2 (EVENT_HINT.md). H2 (overriding readable readings too) was measured and rejected.

(d) The context filler

docs/js/vss-context.js with docs/model/context/weights.json (14.9 KB). It runs after VSS on the chosen reading and handles reference gaps in the entity roles (target, from, to, anchor): pron (“it”, “them”), vague (“the new one”), desc (“the blue one”: filled only by a context shape whose known attributes confirm it, otherwise left to the engine as a mention) and empty (a role the action needs but the reading left empty; the needs are learned from the gold args). Candidates are a closed set (shapes created or named earlier in the message, shapes on the canvas, names in the text, recent groups); hard filters (one vs several, description constraints, recency); a linear ranker with 155 features and a learned “nobody” candidate, trained by training/sketch/train_context.mjs on the gold args of an 80% split. Decision: fill with the best candidate when it beats the runner-up by the margin; the margin is 0 (owner, 2026-11-01: in drawing a mistake costs one undo, a question costs more), so it asks only when “nobody” ranks first. A request with a gap it cannot fill becomes a question to the user, not an execution.

(e) The adapter to SOP wires

docs/js/vss-adapter.js: readingFromWires turns the reader's wires into an event with roles; toNodes maps the roles to SOP keys and values (a description in a role becomes a mention wire). Position values are placed by what they are: a relation (left_of, below, between, …) is a relation and a region (top_left, center, …) is a region, whichever of relation, region, relation2 holds it (fix 1 of SHORT2.md, 2026-11-02: before, such a value was dropped silently).

How a unit is decided, and ties

  1. Every candidate world reads the unit with its own front end (after H1 where it applies).
  2. The reading that leaves the fewest words not understood wins: the unit's surface words, punctuation excluded, that are not behind a role filler, an accepted offer or the action token (the count of training/sketch/words_not_understood.mjs). An unreadable status (unknown-event, no-sense) understands no word; a reading that understands no word is not a reading.
  3. A tie goes to the context layer (chooseReading in vss-context.js: the reading the message context can complete); if still tied, the cutter's order (the higher B-<world> score).
  4. No reading: the unit is ignored and the reply says what was not understood.
  5. The context filler then fills or asks; the adapter writes the wires; the references (names created, last) carry to the next unit (nextContext).

No fallback world. The general fallback model kinds_p80_s0 was removed from the composer and the registry on 2026-11-02: it read 0 of 4643 requests on the sample and 0 of 877 on the short sets, and the numbers were identical without it (SHORT2.md §7). A unit no candidate world reads is reported as not understood. The model folder is in git history (commit a76b4e3).

Also in the code, off by default: need_read (re-read an empty needed role with presence “all”; tested, not adopted, SHORT2.md §6). Removed on 2026-11-02: the single-model VSS path (?vss=single) and the older token router (the composer accepts only "router": "cutter").

6The spell checker

docs/js/spell.js (SpellKit) runs on the message before any reader. It is built with VSA, not a dictionary algorithm: every word is a hypervector, the bundle (sum) of random bipolar vectors of its character n-grams with ^ and $ marking start and end; the cosine of two word vectors estimates how many n-grams they share. A word that is neither known nor kept is replaced by the nearest known word when the cosine is at least threshold and at least margin above the second-best.

Vocabulary (targets)
478 words in docs/model/spell/vocab.json (the VSS worlds' lexicon, catalog, value and trigger phrases, built by training/sketch/spell/build_spell.mjs), plus at run time the legend's values and cue words and the names on the active reader's canvas.
Kept words
2506 words that occur in 2+ training messages (“wants”, “flow”, “because”): never corrected and never a target.
Parameters
D 1024, n-grams of 2 and 3 letters, threshold 0.40, margin 0.06, chosen once by the protocol in build_spell.mjs: one random typo per message of the 1128 benchmark messages (seed 1), objective right − 3·wrong − 3·false corrections; result 596 right, 66 wrong, 405 left, 3 false corrections. Stored in vocab.json (the defaults in spell.js are overridden).
Left alone
Known words, words of 1–2 letters, numbers and words with digits or apostrophes, quoted text, the word after named / called / titled / labeled, and capitalised words inside a sentence (names: corrected only toward a name on the canvas, “Strat” → “Start”).

vocab.json lists kinds_p80_s0 among its source models: it was built before the fallback world was removed and has not been rebuilt since.

7Models and versions

Versions: the browser never uses a stale model

training/sketch/stamp_models.py computes a content version for every model: the first 10 hex digits of a sha256 over the model's files (relative path + content, sorted; BUILD.json left out). Folder models are the VSS folders (with manifest.json) and the transformers.js folders under neural/; file models are the cutters, context/*.json and spell/*.json. It writes docs/model/versions.json (15 entries; plus file sizes of the neural folders, shown before download) and the same versions into registry.json (version per world, cutter_version, event_cutter_version, context_version). It is idempotent and is run before every commit that changes a model.

The loader (versioned() in docs/js/vss-formalizer.js) appends ?v=<version> of the longest matching folder or file to every model URL. versions.json and registry.json are fetched with cache: "no-cache" (always revalidated). The neural files are requested from transformers.js as a Hugging Face URL whose revision is our version, and a custom cache maps that key to our versioned file; the Hugging Face models (only used by the headless comparisons) are pinned to a commit.

Hosts that cannot serve binary files: the loader can fall back to base64 parts listed in a bin-parts.json inside the model folder (the manifest's sha256 still checks them). GitHub Pages serves the .bin files directly.

8Data

All training data are realistic messages written by LLM agents (Sonnet, Haiku) in the style of real use: whole messages of 1 to 20 sentences, with chatter, self-corrections, typos, many domains and personas, and the requests annotated as spans ({id, names, text, wires: [{span, trigger, type, args}]}). Specifications: training/sketch/llm_train/TRAIN_MSG_SPEC.md, training/sketch/llm_bench/SPEC.md, training/sketch/LABEL_CONVENTIONS.md; the writing and checking procedure is the skill skills/llm-annotated-data/SKILL.md.

Rules (AGENTS.md). A data writer saves its texts before annotating (one file per batch, ids and texts only); the coordinator checks that the annotated texts are byte-identical to the saved ones; a text is never edited to fit an annotation (2026-10-31: two writers did). Realistic examples are never dropped because the pipeline cannot read them. Template sentences (training/sketch/generate.py) are at most a secondary, labelled variant. There is no hidden test set (owner, 2026-11-01): every annotated message is data and may be read, analysed and trained on; worlds are measured on the data they are trained on and on similar data.

10Measurement and the current numbers

The metric (owner, 2026-11-01)

Per requested action, never per message: of the gold requests, the share done right, done wrong (executed with the wrong action, shape or value), and not done (not understood, or asked back); plus extra: the count of requests nobody asked for. Wrong is worse than not done: decisions weigh “done wrong” first, then “right”. A reference the reader leaves for the context (“it”, a name from an earlier sentence) is not an error. Questions back to the user have a cost too: ask as little as possible.

training/sketch/llm_score.mjs
Scores a reader on folders of annotated messages. SEG=composer: the whole composer on whole messages; SEG=gold with MODEL=micro/<world>: one world on gold spans (no cut). PAIR=value pairs produced and gold requests by their values. Also scores the Rules reader.
training/sketch/short_bench/
short_bench.mjs (the demo's six sets, called as the demo calls the reader), agg.py (per set), classify.py (the cause of each miss: A no unit, B partial unit, C right world not a candidate, D unknown-event, E wrong event, F lost to another world, G1/G2 the filler asks, H1/H2 role values).
training/sketch/error_analysis.mjs
Root causes of one world's misses on perfectly cut requests: A action word not recognized, B wrong action, C reader refuses, D value not reachable, E name not reachable, F role missed, G role wrong.
training/laptop/neural_score.mjs
Rules, VSS and Neural on the same gold, with the scoring of llm_score.mjs, plus milliseconds per message.
Discipline (AGENTS.md “Experiments”). Before a run: the hypothesis, the measure and the threshold for “it worked”, written down and shown (the “pre-registered” documents of section 11). No knobs turned on the fly; one change at a time; a miss is reported, not patched. After every evaluation: a root-cause analysis of the misses, each classified by the first cause that explains it and where it sits (data, front end, our code, calibration, model); fixes go where the cause is.
