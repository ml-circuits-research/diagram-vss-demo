Follow one explicit distance from text to target

Create a circle 20 px right of Box.

Faithful SOP frame:

@c1 command action=create shape=circle position=rightOf anchor=Box distance=20

The different frame discussed below:

@c1 command action=create shape=circle position=rightOf anchor=Box

The reader’s job ends with the first frame. It does not need to know Box’s coordinates or choose the new circle’s final x and y. Those calculations belong to the symbolic system. It does need to preserve 20, because the user stated it. The second frame changes an exact displacement into an unspecified one.

The shipped VSS conversion recipe does not carry anchored distance in the way the later GAP_ROLE=1 option does. More generally, conversion uses a soft mode: a request can remain in the dataset while a role that cannot be aligned or represented is omitted. This keeps realistic text, which is good, but it can turn a full annotated answer into incomplete supervision.

If the reduced target is treated as a complete answer, training rewards the omission. More epochs then optimize the wrong target more thoroughly. This is not a VSS capacity result; the loss occurred before optimization.

Consider three inputs. “Create a circle right of Box” genuinely leaves the distance unspecified. “Create a circle 20 px right of Box” specifies it. “Move it right” supplies a reference whose referent may require context. These cases must not all become an empty role interpreted as “nothing was requested here.” The second needs repaired conversion or an explicit incomplete-target status. The third needs a preserved reference, not a guessed object name.

A target round trip tests this without a model: take the annotation, convert it into the training representation, reconstruct SOP, and compare the semantic fields. Earlier scene analysis reported 57.1% for scenes_test and 49.9% for scenes_r3 through the shipped VSS fronts. Those are historical results for that path, using the existing scoring conventions. They are evidence of conversion loss, not an upper bound on every possible VSS model. Source: ROOT_CAUSES.md.

Repair supervision without simplifying the real messages

Keep the original message and annotation. For every role, record whether it was stated, whether it is represented in the training target, and whether it is intentionally unresolved. A conversion failure should be visible by message ID, source span, role and reason. It must not silently become a negative example for that role.

Then repair the specific representation or alignment that loses distance, dimensions or a description filter. When a role truly cannot be represented yet, preserve the message in the audit and choose an explicit partial-supervision policy under a registered protocol. Do not rewrite or discard realistic messages merely to make the current converter succeed.

The acceptance condition is concrete: annotation → training target → SOP must retain distance=20; an unstated distance must stay unstated; an unresolved pronoun must stay a reference. These checks precede retraining. A later model comparison can then ask whether the repaired supervision raises faithful-frame coverage at the same rate of confident false assertions.
