05 / representation

The pipeline must not turn lost information into a complete-looking frame.

A sign, a quoted label, one coordinate or unread text can be lost mechanically. A symbolic executor cannot recover the user’s original intent from a frame that hides that loss.

Preserve literal values and carry an explicit incomplete-reading status to the consumer.

A coordinate is not an optional decoration

Draw a square named Walls at 400, 300.

Faithful SOP frame:

@c1 command action=create shape=square name=Walls at=400,300

The different frame discussed below:

@c1 command action=create shape=square name=Walls

Suppose the world reads x=400 but misses y=300. The adapter requires both coordinates to emit at, so it drops the whole point. The remaining frame is valid SOP, but it no longer says that the user requested an explicit location. An executor may place the square by default, and nothing in the reduced frame explains why that is incomplete.

The reader may legitimately be unsure of y. The required behavior is to preserve the partial reading and mark the point as unresolved. The consumer can ask for clarification or hold the operation. It must not infer “location was not specified” from “the reader failed to recover the location.” A confidence gate may catch the failure accidentally; the missing-field status should not depend on that accident.

The same problem can occur before the model sees the request

Compare “Move Box to -20, 30” with “Move Box to 20, 30”. The inspected VSS tokenizer produces the same normalized token values: the leading minus is not retained. The source offsets differ, but the world’s value input no longer distinguishes the two meanings. No deterministic model can recover a removed sign from two identical normalized inputs. If negative coordinates are unsupported, the reader must report that restriction, not silently change the number.

Quoted text has another collision. “A+B” and “A B” both produce the slug t_a_b. When the two literals share one tokenization call, the dictionary keeps only the first literal for that ID. This is an invalid copy path. Separate calls may avoid a particular collision, so the probe does not establish how often whole messages fail; it establishes that the identity scheme can erase distinct strings.

SOP-BERT’s cutter has a different mechanical limit: it reads at most 512 wordpieces, and its request reader uses a shorter 128-piece limit. The cut decoder assigns words beyond the inspected input pO=1, as if they were known to lie outside a request. Unread text is not evidence of “no instruction here.” A correction or an additional action in that suffix cannot be recognized by more training while the cap stays unchanged.

Preserve values, and make incomplete reading explicit

Use exact literal IDs and signed numeric values consistently through tokenization, target preparation and SOP assembly. Retain source offsets so each field can be traced to text. For a partially read point, retain both the known coordinate and the unresolved role in the returned record. For truncation, return the unread text interval instead of declaring those tokens irrelevant.

A proposed interface can carry a valid partial SOP program plus metadata listing unresolved fields and unread spans. Alternatively, SOP can gain an explicit reference/unknown construct. Either is an interface proposal requiring a deliberate schema decision; neither is claimed to exist in the current engine. Other independent requests can still be handed over faithfully.

Acceptance checks: the two signed values remain distinct; the two quoted labels remain distinct; a missing y produces an incomplete-point record; a truncated suffix is reported as unread. These checks measure information preservation, not model intelligence. The earlier house report observed lost y in 3 of 8 creates for its VSS run, but the frequency of the other losses in production remains unmeasured.
