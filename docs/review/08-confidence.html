08 / measurement

Confidence must estimate whether the SOP frame is faithful.

A confidence number is useful only if its right/wrong labels mean “this is what the text said”, and if unresolved references are not confused with false assertions.

Separate frame fidelity from readiness to execute against a particular world.

A clear instruction can still have an unresolved target

Move it 20 px left.

The reader can identify move, distance 20, direction left, and the target expression “it”. That can be a faithful reading even when the object referred to is unknown. The symbolic layer may resolve it from context or ask the user. The reader should not replace “it” with Box solely to produce an executable-looking command.

This creates two separate decisions. Is the returned frame faithful to the sentence? And does the symbolic consumer now have enough information to execute it? The first can be high-confidence while the second is still blocked. A single success label based only on execution can hide that distinction.

The current production metric remains valuable for the whole system: among operations it executes, how many are wrong; and how many requested operations it does right. But to assess the language technology itself, add a frame-level view that accepts explicit unresolved references and penalizes unsupported concrete values.

Where the current confidence can be misled

The confidence collector uses the same permissive argument comparison described in problems 1–2. An extra shape change can therefore receive a “right” label. Fitting a probability to that label does not estimate true frame fidelity. Repair the target event first; merely moving the threshold cannot correct a mislabeled training objective.

Agreement is also evidence, not a certificate. If VSS and SOP-BERT both lose an annotated distance, they can agree exactly on an incomplete frame. Their different architectures do not make their errors independent when annotations, conversions or cuts are shared. A historical experiment recorded 23 wrong agreements on a then-unseen short set; that demonstrates a possible failure mode, not the current shipped rate. Source: confidence3/RESULT.md.

Finally, the offline gated scorer can retain the right/wrong outcome computed with all readings available, then filter by confidence. In the actual application, holding a create can also block a later reference to it. The UI already has dependency checks. The approximation is in the offline report, so it can overstate useful coverage relative to the actual gated execution path.

Calibrate two explicit boundaries

For the reader boundary, label complete faithful frames, faithful partial frames with explicit unresolved content, false frames and extra invented requests. Fit confidence using out-of-fold predictions and corrected labels. Report how many intended requests are represented faithfully at a fixed rate of confident false assertions. Keep unresolved-role counts visible so “always uncertain” cannot masquerade as useful understanding.

For the execution boundary, use the real resolver and dependency gate, then retain the repository’s precision, correct-request share and cost score. With 10 requested actions, 4 correct executions, 1 wrong execution and 5 held requests, execution risk is 1/5=20%, correct coverage is 4/10=40%, and cost-10 utility is 100×(4−10)/10=−60. The five held requests are not five errors. They are five requests still not performed.

Choose each threshold by the registered rule on its calibration data, then measure it unchanged on the comparison data. Recheck when the request mixture changes. A threshold maximizing cost-10 utility is not a mathematical guarantee of a chosen precision on every future sentence. This proposal refines attribution; it does not remove the existing execution-risk metric.
