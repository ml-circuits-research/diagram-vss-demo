06 / data

A reader comparison also compares its training data unless the data is held fixed.

The world, its cutters and SOP-BERT are trained from different declared message sets. That can affect which constructions they recognize before any architectural difference is measured.

Record the actual texts and semantic-role coverage seen by every trained part.

One message has to survive several learned decisions

Consider “Add a red square and a blue circle near Red1”. A cutter must retain both requested creates; a value reader must associate red with square and blue with circle; conversion must retain the relation to Red1. If one learned part saw coordinated whole messages and another saw mostly isolated literal commands, the full reader may fail at their boundary. This is an example of the question to investigate, not a measured attribution to data mixture.

The current loader recipes differ in a directly inspectable way. They include different groups of short messages and former benchmark-span messages. Reusing benchmark data is allowed by this repository’s policy; the issue is whether a comparison names what each model actually learned from.

How this changes what the model learns

A message with ten requests can yield ten request-training rows. A short literal command may yield one. Counting files or messages therefore does not tell us the effective training weight. In the reconstructed SOP-BERT corpus, 21,362 of 54,584 annotated requests came from synth_* folders: 39.1%. That is a substantial share of supervised requests.

Literal commands are required by the project and are useful: they cover the grammar people try when a longer request fails. Their presence is not the problem. The engineering problem is not knowing whether, for example, a new batch increases count=2 creates while leaving corrections, negation or width/height roles almost absent. The data inventory should expose that before a run.

Other recipe evidence is in make_data.py, the world-cutter artifact, the event-cutter artifact and the world BUILD record. Only 85 excess exact case-insensitive duplicate messages were found in that reconstruction. Exact duplication alone is not demonstrated to be the main cause of poor reading.

Make the comparison attributable

Save a manifest with file hashes, message IDs and converted-row counts for each trained part. Add counts by action, semantic role, construction and source. Include failures of conversion in that inventory; excluding difficult realistic examples would conceal a coverage gap.

For an architecture comparison, use the same annotated messages and document any necessary representation difference. For a data experiment, keep the architecture fixed and change one sampling or coverage decision under a predeclared protocol. Compare faithful SOP frames, explicitly unresolved requests and confident false assertions. Keep short literal commands and realistic multi-request messages visible separately.

Do not conclude that synthetic data, deduplication or long messages caused a regression when several ingredients changed together. The review establishes different input recipes; it does not establish the isolated performance gain from aligning them.
