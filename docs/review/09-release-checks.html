Make a validated model/data/code identity part of every successful build and cached result.

The failure path matters as much as the successful path

A training/export pipeline should establish that Python and JavaScript read the same artifact in the same way. If they disagree, the result should be a failed candidate build. In confidence3/refit.sh, mandatory-looking checks are instead followed by || echo failure messages; the script can continue to version stamping and print “done”.

The practical risk is concrete: a reviewer sees a finished build and interprets its score as evidence about the model, although the Python/browser equivalence check failed. The review establishes this continuation path. It does not establish that a currently shipped artifact was corrupted by it.

The SOP-BERT export workflow in finetune_roles.py can similarly retain agree=None after a failed Node check. “Not checked”, “check failed” and “check passed” need different build outcomes. None of those checks establishes semantic correctness; they establish that the same program is being measured and shipped.

Why a familiar cache filename is insufficient

Suppose yesterday’s registry.json selected model A and today’s registry.json selects model B. A cache named only from the registry basename can still contain A’s readings. Unless the caller forces a rebuild, the existing file is returned before model loading. A downstream confidence fit or error report can then appear to measure B while consuming A’s frames.

For the language-to-SOP contract, this blocks a basic engineering question: did this exact reader preserve the arguments of this exact message? Without provenance, an error cannot be reliably attributed to the model, converter or old predictions. Again, this is a demonstrated possible code path, not evidence that every historical report used stale results.

A small, checkable build contract

Construct a candidate bundle separately, run the required parity and schema checks, and accept the bundle only if they pass. A failed mandatory check must return a failure status before stamping or promotion. Record hashes of weights, layout, preprocessing, confidence files and evaluated data. Cached readings must carry the identities of the inputs that produced them; reject reuse when an identity changes.

Test this by deliberately making a required check fail: the candidate must remain unaccepted. Then change one input hash: the old cache must be rejected. These are engineering checks, not training experiments. Also keep small semantic cases such as an added shape argument and a lost minus sign, because two implementations can agree perfectly on the same wrong behavior.

The intended outcome is a reproducible chain: message and annotation → exact reader build → emitted SOP frame → comparison result. That chain must be reliable before differences in scores can support decisions about VSS or fine-tuning.
