What could prevent VSS or SOP-BERT from returning a faithful frame?

The question is not whether either reader can solve the whole world behind a sentence. It is whether it can preserve the intent, including what remains unresolved, without adding unsupported assertions.

Several current limits are repairable interface losses. The remaining model limitations need isolated experiments, not claims based on the final drawing alone.

Unresolved meaning is allowed; invented certainty is not

Move it 20 px left.

A faithful reader can report move, 20 px, left, and the reference expression “it”. It does not have to identify the object. If two objects fit the context, the symbolic resolver or an agent can ask which one. That is not a failure of language formalization. A reading that silently changes “it” into Box is a stronger claim than the text supports and must be justified by a separately identified context step.

Likewise, “How many red circles are there?” should yield a count question with shape=circle and color=red. The reader should not invent the answer 3. The symbolic system evaluates the query against its state. Preserving the question is the language task; answering it is another task.

This makes “perfect” a precise question. On a bounded, explicitly specified language, a parser can meet an exact formalization contract. For unrestricted future wording, a finite observed error rate does not prove that a learned reader will never assert something false. No experiment in this review establishes an unavoidable error percentage for VSS or SOP-BERT. The achievable useful coverage at a chosen false-frame rate remains an empirical question.

Two limits that more training cannot remove

The first limit is lost input. If preprocessing makes “−20” and “20” identical, a deterministic downstream reader receives the same input for different intended values. It cannot reliably choose both original answers. Preserve the sign before experimenting with the model. The same reasoning applies when two distinct quoted strings share one literal ID.

The second limit is an incompatible output contract. A real annotated message, sm-0194, contains:

Add a red square and a blue circle near Red1.

The annotation assigns that exact span to two create requests, one with shape=square/color=red and another with shape=circle/color=blue. The request builder emits two rows with the same text and the same earlier-name context. A single-frame decoder is then asked to give two different single answers to the same input. It can fit one or trade between them, but it cannot satisfy both simultaneously without an occurrence selector or multi-event output.

The original annotation is in msg_04.jsonl, sm-0194. SOP-BERT’s B/I/O cutter also cannot label two overlapping event instances on the same words in its present one-tag-per-word format. This is not a proof that transformers or VSS cannot understand coordination. It identifies a mismatch between annotation and interface. A split that carries the shared verb, or a decoder that emits two event instances with separate argument assignments, could address it.

The model-specific risks after those losses are repaired

For VSS, early learned lexical replacements may collapse meaning; vector composition can mix competing fillers; cleanup can pick a wrong name or value even when overall cosine improves. The front’s wide→rectangle association is a concrete example of an overly strong early decision. Interference or insufficient dimension are plausible further causes, but their contribution is not isolated by the current aggregate scores. Fixed phase correction cannot recover a distinction already erased from the state.

For SOP-BERT, the current joint output has one action/value frame per request and one tag per word. Missing width/height outputs, a limited class vocabulary and truncation are concrete restrictions. Fine-tuning may also learn correlations that fail on a new construction, and it may reduce useful transfer for unseen words. Those latter risks need measurements; they cannot be diagnosed merely from one unfamiliar synonym failing.

Neither training objective directly guarantees faithful SOP. VSS optimizes vector similarity; SOP-BERT optimizes class/tag losses. A role may still be wrong at a low loss. Confidence can reduce how often unsupported frames are handed over, but it inherits the quality of its correctness labels and the distribution on which it was calibrated. Agreement between models with shared supervision can repeat the same mistake.

The correct isolation experiment supplies faithful input values, faithful targets and appropriate request/event boundaries, then evaluates the raw semantic frames. Context resolution and final execution are measured separately. Only after that separation can a residual error be attributed to the chosen learning/decoding method.

Alternative approaches, with the failure each one targets

First: a typed partial-frame contract. Keep known fields, explicit unresolved references and unread spans. Give every asserted value its source span or an explicit “derived by context/default” origin. This directly prevents failed extraction from becoming apparently intentional absence. It is an interface/schema proposal, not a new trained model. Schema validation alone cannot detect a plausible but wrong color; it must accompany semantic evaluation.

Second: represent multiple events and their relations. For the square/circle sentence, emit two create events, each with its own color and shape, while preserving the shared source words. For a self-correction, represent which proposal was retracted. A structured event/argument decoder, or a carefully defined split-and-inherit representation, can be compared on exactly the same real messages. A sequential decoder constrained to SOP syntax is another candidate, but valid syntax does not guarantee correct intent.

Third: retain candidate frames when the text does not justify one. A symbolic consumer can reject impossible types, check named objects, and ask about remaining alternatives. It must not call the first valid candidate “the intended one” merely because it can execute it. “A red circle” can match two real objects; checking existence does not solve ambiguity.

Fourth: an explicitly documented literal-language lane. A strict diagram grammar can offer reliable coverage for clear fallback commands, with an honest unsupported response outside that grammar. This is a Rules or hybrid approach and should be named as such; it is not evidence that a learned-only reader acquired those language mappings. Its value can be compared by faithful coverage, not by hiding unsupported texts.

Fifth: an optional general-language proposal or clarification loop. An LLM could propose SOP for difficult wording, with a visible confirmation step before execution. Or the current reader could ask a narrow question about the missing role. These change the product trade-offs and require their own comparisons of correctness, questions and cost. Assisted confirmed execution must remain distinguishable from autonomous reader accuracy.

I would test faithful conversion and the partial-frame contract first, then the multi-event representation on the identified same-span cases. A larger encoder or a different vector algebra is easier to assess once the correct answer is expressible and preserved. New learned models or replacement pipeline layers remain proposals requiring the owner’s architecture decision.
