SOP-BERT cannot emit fields that its output layout does not contain.

The fine-tuned encoder may recognize the words, but the exported reader still needs an output for every semantic field the text states.

Output coverage is a prerequisite for learning the intended SOP frame.

Four numbers, four different roles

Draw a black rectangle 150 by 90 at 700, 300.

Faithful SOP frame:

@c1 command action=create shape=rectangle color=black width=150 height=90 at=700,300

The reader must associate 150 with width, 90 with height and the other two numbers with the point. It does not need to draw the rectangle. The symbolic engine can instantiate it once these fields are available. If the reader cannot distinguish the numbers, an honest result identifies the unresolved roles instead of presenting a default-sized rectangle as the complete request.

The shipped SOP-BERT layout has coordinate extraction but no width or height span outputs. It also omits distance from the keys allowed for create, and its fill choices are limited to an absent value and light. This is a precise limitation of that exported reader. Changing the learning rate or training for more epochs with the same layout cannot add an output it has no way to select.

How training coverage becomes a hard output restriction

The data builder discovers fields used in the annotations and builds the output layout from them. Some outputs are class choices, such as color. Others are token tags that identify where a value is written. The per-action key list then tells the JavaScript decoder which fields to assemble into SOP. A field absent from this layout is unavailable even if the encoder has useful features for it.

The scene root-cause report gives an associated failure: dimension numbers were sometimes tagged as coordinates. When the coordinate decoder received four numbers instead of two, it dropped the point. Missing width/height coverage could therefore damage both the dimensions and the location. That downstream result must be distinguished from the simpler structural fact that the missing output slots cannot emit those roles.

The same preparation step learned some number-word associations from co-occurrence: words such as “lights”, “circles” and “duplicate” acquired the value 2 in inspected data. A noun or operation often appearing beside count=2 is not itself a spelling of 2. This is another place where the answer can be contaminated before the encoder is judged.

Inspected artifacts: the shipped config.json and make_roles.py. Earlier label-path round trips on scenes_test rose from 71.8% to 89.0% when scene training annotations were included, or 100% under that report’s allowance for context-delegated references. These are representation checks, not gains measured after a new fine-tune.

Check the schema before spending another training run

Build a coverage table from the legend and annotations: for each operation, can every supported argument and value be represented in the training target and emitted in SOP? Test explicit no-fill separately from a missing fill request. For numeric words, require evidence linking the word span to the value; sentence-level co-occurrence is insufficient.

An oracle output test should populate the correct tags/classes directly and reconstruct the expected wire above. If width=150 or height=90 still disappears, the decoder/layout path is the cause and no encoder experiment can fix it. After the layout is faithful, training can be measured on choosing the right fields and on marking uncertain ones honestly. Report the round-trip result and the trained-reader result separately.
