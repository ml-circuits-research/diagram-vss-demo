Future experiments: what each proposal would actually change.

This reviews all 12 proposals and subproposals in source order. Each judgment asks whether the change would preserve natural-language intent more faithfully in SOP.

Repair the semantic reference and output contract first; otherwise a model can improve the reported score without improving its reading.

The question each experiment must answer

The target is a reader that returns the intended operation, roles, literals and unresolved references for a symbolic consumer. It need not choose drawing defaults or resolve pronouns. A useful experiment must say which failure at that boundary it targets: missing action, wrong role, lost value, invented argument or unreported uncertainty.

The proposal file future-experiments.md contains six main headings, with three vector-code options and five Rules/VSS options. Each is discussed below. These are judgments about experiment design, not results of new runs. Historical percentages retain their original model/data scope.

Whenever a proposal below mentions the cost score or executed actions, keep that existing full-system measurement, but add the faithful-frame comparison before context filling. A gain in drawing execution must not be mistaken for improved text understanding if it came from a better context guess. Conversely, correctly preserving “it” as unresolved must not be counted as a language failure.

1. Read the action from the construction

Promising, after refreshing the baseline.

It addresses a real limitation: an action can be expressed without a familiar verb. “Post blue” should not fail solely because no verb was found.

The text describes an older reader. The shipped reader already permits an event hint to satisfy the verb check, and front-end pattern rules can insert an event token. Compare against this actual baseline. Also, an action role can be circular if decoding the rest of the frame already requires choosing the action. The proposal must specify how competing actions and their roles are scored jointly.

“Post blue” may be an instruction to recolor Post, or a statement that Post is blue. Syntax alone does not reveal the user’s intent when both uses are allowed.

Keep the same data and worlds; compare current H1 with action-from-construction decoding. Include commands, facts, default rules, noun-led creates and text outside requests. Use correct/abstained/wrong/extra per action, then the full composer with refitted confidence. Adopt only for a gain at the registered risk/utility target, not merely fewer unknown-event statuses. This changes the reader and requires an architecture decision before implementation.

2. Catastrophic forgetting and LoRA

A useful diagnosis; LoRA is a candidate remedy, not a proof against forgetting.

Tracking unseen trigger words during fine-tuning can reveal a loss that ordinary in-domain accuracy hides. Comparing smaller learning rates is a sensible control.

The proposal starts from the old act classifier; the shipped reader is a joint cutter/action/role model. A frozen base with a newly trained head is needed as a relevant control: an untrained task head does not give a meaningful baseline. Drift and masked-language loss are diagnostics, not evidence that diagram commands got worse. Even with frozen base weights, the active adapter changes the function and can reduce transfer. Separate adapters isolate their own parameters only if the shared base, heads and router also stay fixed.

If “erase” never occurs in task training, the failure may be weak transfer from pretrained features, a new head that learned only “delete,” missing negative examples, or forgetting. Observing one failure does not identify which.

Use the current joint reader and a predeclared trigger/form split. Compare full fine-tuning, a lower learning rate, frozen encoder with trained heads, and a small fixed LoRA grid. Match data and report both updates and compute cost; equal epochs alone is not equal cost. Check action, roles, cut-induced errors and risk-coverage. Measure merged/exported/browser parity. The original LoRA paper establishes low-rank updates with frozen base weights; the task-specific forgetting conclusions here are hypotheses, not results from that paper.

3. ModernBERT as the encoder

Worth a controlled comparison after output and truncation fixes.

A different encoder can plausibly improve contextual cutting and role reading. The official model card describes a 149-million-parameter base and an 8,192-token native context.

It is not a one-argument swap in this repository: finetune_roles.py explicitly rejects encoders whose model_type is not distilbert, and the heads use DistilBERT configuration fields. The current reader also hard-codes 512/128 limits. A longer-context base does not help while those caps remain. Published tasks do not establish a gain on this legend; the proposed training times and browser slowdown are estimates, not measurements.

A ModernBERT encoder behind the same layout still cannot output width if width has no tag. It can also still discard the end of a message if the wrapper truncates it at 512 pieces.

First run a tiny custom-head export and browser-parity feasibility check. Then compare against corrected DistilBERT with identical data and heads, reporting both short and genuinely long requests, cold download/load and warm WASM latency. Current Transformers.js documentation lists ModernBERT; that does not certify this project’s custom multi-output export or every pinned runtime. Verify the exact version and export together. A new encoder needs approval before implementation.

4. A second legend with costly wrong actions

Useful for testing transfer of the method, not for establishing operational safety.

It tests whether performance depends on the diagram legend and whether the confidence method adapts to asymmetric error costs. Keeping it a research bench is the right boundary.

The diagram domain can already test stringent precision targets. A second domain is not required to expose weak calibration. LLM-written messages and unchecked annotations do not validate domain correctness. Also, transferring a numerical threshold between independently calibrated models is not inherently meaningful: transfer the fitting protocol first, and treat raw-threshold transfer as a separate stress test.

For an abstract transfer legend, confusing 10 with 100 or swapping account A and B is a different mistake from omitting a nonessential note. The annotation and score must preserve amounts, signs, units and entity identities.

Begin with a purely simulated, deterministic domain and audited annotations. Fix risk targets, allowed abstentions and error categories beforehand. Report confidence intervals on the executed requests and useful coverage. Under an independent Bernoulli model, zero errors in n executions gives a one-sided 95% upper error bound of 1 − 0.05^(1/n); zero in 100 is about 3%, not proof of near-perfect safety. Correlated scenarios need grouped analysis. No real transactions or clinical use are proposed.

5a. Reduce VSS dimension to 512 or 256

A good efficiency experiment, not a first accuracy repair.

It changes one clear variable and asks whether the application can use a smaller model. Measuring by request length is useful.

Update seven worlds to the actual nine-world baseline. Download bytes and browser computation do not necessarily halve with D because routing, preprocessing and fixed overhead remain. “Within the baseline bootstrap interval” is not a sound non-inferiority rule: overlapping uncertainty can hide a meaningful loss.

A short request with several names and repeated values may be harder than a longer sentence with mostly filler words. Length alone does not measure the number of competing role fillers.

Keep data, code, seeds and conversion fixed. Report by length, number of names, roles and repeated values. Refit each model’s confidence using the same protocol. Predeclare an allowed utility loss and test the paired difference against that margin, while enforcing the agreed wrong-execution constraint. Measure real bytes and latency. Do not infer capacity improvement from compression.

5b. Replace phases with binary vectors

The idea is legitimate; the proposed direct conversion needs redesign.

Binary storage and bit operations are plausible efficiency tools. Separating conversion feasibility from a new trainer is sensible.

Taking the sign of the real part does not preserve phase binding as XOR. This is a change of algebra, not just stronger quantization. The existing routebook cannot be assumed to keep its meaning under it. Also, a trained D=1024 routebook does not acquire learned extra dimensions merely by asking for D=2048 “without retraining.” The stated 8× saving compares one representation vector; it does not establish 8× smaller complete models or runtime memory.

Take phases 60° and 60°. Both have positive real parts. Their product has phase 120° and a negative real part. Encoding positive as bit 0 gives 0 XOR 0 = 0, while the bound phase would encode as 1. The operations disagree.

Before model benchmarks, specify the new binding, bundling, inverse and decoding contracts. Test those operations against known symbolic frames, including repeated bindings. Then compare a properly trained binary model against phase quantization and smaller-D baselines at matched utility. Straight-through training is an architectural experiment with its own failure modes, not a guaranteed export fix.

5c. Real HRR and sparse block codes

Reasonable later research, presently too underspecified.

Alternative codes could offer different storage, interference and execution trade-offs. A common semantic benchmark is the right basis for comparison.

“Other codes” covers different representations and trainers. A poor adapter between codes could look like a weakness of the representation. Not every vector in the current system has unit modulus: identity stars do, but composed states are sums and need not. Comparisons must specify which arrays and operations are being replaced.

A code that retrieves a single bound role well may still confuse two similar names or an ordered list. A retrieval demonstration is not yet a language formalizer.

Choose one code and one stated bottleneck. Specify representation of names, values, lists and role order; verify exact symbolic encode/decode and measure the full bytes/latency footprint. Only then train on the same faithful data and compare executed meaning. Keep this behind the cheaper conversion, decoder and dimension investigations.

6a. A Rules constellation in VSS space

An interesting confidence feature if its conversion is faithful.

It can measure graded disagreement rather than just exact wire equality. Per-role disagreement can be more interpretable than a single global similarity.

The Rules reading must be compiled into the target representation using the same roles, stars and literal identities. “Encode with the route book” conflates two different paths: composing text versus compiling a known symbolic frame. Unsupported or omitted fields must not silently disappear from the reference. High vector similarity can coexist with a wrong target or amount. Selecting a feature on calibration is not a final evaluation.

Two frames share create, circle, red and name, but disagree on the exact anchor. Their total vector similarity may stay high even though the new shape appears next to the wrong object.

Audit the Rules-frame conversion first. Add one similarity feature to the existing confidence fit, with cross-fitted predictions where needed; compare against a simpler per-role symbolic-disagreement feature. Select on calibration and judge on the registered evaluation part. Measure incremental cost-score and risk-coverage benefit, not just a higher AUROC on the fitting data. Rules output remains evidence, not ground truth.

6b. A world-level correction operator

A cheap, well-bounded experiment, with a narrow theoretical reach.

The phase variant already has an explicit objective, a frozen routebook, a closed-form fit and calibration through the corrected state. That makes it easier to attribute any change.

One shared rotation can correct a consistent offset, but cannot recover an omitted role or give different corrections to identical states. Multiplication by fixed unit phases preserves distances between states; it changes their alignment to the fixed decoder, not their information content. A higher cosine need not change any winning role. The document’s job-080/R2 reference is stale: TRAIN_PLAN_R3 specifies jobs 084/085, R3C versus R3.

The documented layout smoke run raised training cosine from 0.7175 to 0.7222, but role decoding stayed 90.3%. That is optimization progress without a demonstrated execution gain; it is not a failure to report.

Use the current R3C-versus-R3 protocol with the corrected semantic score. Keep fronts, cutters, filler and data fixed, and refit confidence equally. Require an faithful-frame benefit and a separately reported execution benefit under the registered criterion. Per-event correction, low-rank maps and joint training are separate experiments; do not add them after a failed phase run to rescue the result. See fit_corr() and the current plan.

6c. Learn confidence for Rules

High practical value, once the scoring labels are fixed.

Rules can be wrong and have useful observable failure clues. Giving them an abstention policy enables a more informative comparison with learned readers.

A confidence model can become an opaque substitute for understanding coverage if it sees only familiar successful templates. It needs realistic failures and texts with no request. Adding VSS/BERT agreement changes inference cost and error dependence; that is a separate variant from using Rules-only evidence. It is also a new learned model, so repository policy requires approval before implementation.

Rules may recognize “delete” in a sentence discussing a possible future edit. A rule-fired flag alone is not evidence that deletion was requested.

Start with a transparent Rules-only feature set and a constant-confidence baseline. Cross-fit on corrected per-action labels. Report Rules ungated, Rules gated and coverage at equal risk. Add cross-reader votes only as a separate controlled variant, including their latency. Audit confident errors by the rule and construction that caused them.

6d. A Rules + VSS tab

Measure the combination before spending effort on a tab.

It may provide a cheaper operating point than running BERT if Rules and VSS complement each other on the current domain.

The quoted 35–50% agreement correctness is from older readers and cannot be reused as a current verdict. Equally, agreement alone is not enough to proceed: shared data can make errors correlated. A tab is presentation, not evidence. Pairing must also preserve the request occurrence and order; the current value matching can pair the wrong occurrences.

Both readers omit the explicit distance and agree on the remaining command. Their agreement is exact, but the executed request is incomplete.

Run current Rules and VSS through a faithful pairing/scoring contract, with the same cut documented. Fit the gate on calibration and judge utility, risk, coverage and CPU time against Rules-only gating, VSS-only and VSS-BERT. Build a UI tab only if a useful measured operating point exists. Do not adopt “two agree” as an unconditional safety rule.

6e. Rules skeleton, learned values

A useful constrained hybrid, but the division of strengths is unproven.

A trusted action/role skeleton can reduce the alternatives a value reader must consider. It might work well for a clearly delimited literal grammar.

The statement “Rules are fragile on values, learned readers on structure” is too broad. The scene analysis shows Rules missing noun-led creates, and VSS losing values. A wrong skeleton can make the right interpretation unavailable to the value reader. This also changes the research claim: the hybrid uses hand-written language mappings for structure and must be reported as such.

If Rules assigns “A blue circle named Sun” to set rather than create, perfectly extracting blue and circle still cannot produce the intended create through that fixed skeleton.

Measure an oracle skeleton first: if perfect structure barely helps, this hybrid is not the bottleneck to pursue. Then replace the oracle with actual Rules output and report the loss. A viable design must abstain or retain alternatives when the skeleton is uncertain. Compare against an explicit grammar-only lane on literal commands. This is a proposed pipeline replacement, requiring approval before implementation.

The order I would use

First fix scoring and the annotation-to-output round trip. Those determine whether subsequent results have the claimed meaning. Then test construction-based action reading, confidence on faithful-frame labels and the existing bounded phase-correction option. Each has a specific question close to the current implementation.

After that, compare fine-tuning protocols, a new encoder or smaller vectors with the same faithful schema and data. Binary codes, a second domain and larger hybrid replacements need their own precise contracts and baselines. No proposed model or pipeline replacement is implemented by this review. Register the hypothesis, measures and acceptance threshold before running; do not select a success criterion after seeing results.
